🔥 About Me

I work as a Security Systems Engineer across the SDLC where security is not a gate — it’s a set of system invariants that remain true regardless of code changes, deployments, or operational stress.

I focus on enforceable architecture and execution: trust boundaries, identity flows, authorization enforcement points, secure defaults, deterministic pipelines, controlled promotions, and runtime guardrails.

I optimize for production guarantees: preventing insecure deployments, reducing blast radius, enforcing least privilege, eliminating silent drift, and ensuring incidents are detectable and containable.

⚖️ Engineering Philosophy

Shift Smart, Not Just Left

Security should be abstracted into the platform. If the paved road is secure, teams ship faster with less risk.

Identity is the Control Plane

Network boundaries are porous. Strong workload identity + OIDC federation enables keyless, verifiable trust.

Guardrails over Gates

Guardrails preserve velocity while preventing catastrophic failures. Enforce safety without blocking delivery.

Detection as Code

Alerts must map to response playbooks. If an alert has no action, it becomes noise and reduces trust.

🧠 Security System Design (What I Build)

1) Trust Architecture (Threat Modeling)

  • identities & principals (human, service, workload)
  • trust zones & cross-boundary flows
  • authorization ownership & enforcement points
  • attacker paths (bypass edges, escalation routes)
Outcome: deny-by-default boundaries + scoped permissions.

2) CI/CD as a Security Control Plane

  • only reviewed changes produce deployable artifacts
  • policy violations fail early (pre-merge + pre-deploy)
  • artifacts traceable to commit + approvals
  • promotions controlled and auditable
Outcome: deterministic security pipelines with evidence.

3) Supply Chain Hardening

  • controlled artifact creation + promotion flows
  • strict versioning (no “latest”)
  • SBOM generation and evidence packaging
  • verification gates with consistent meaning
Outcome: tamper resistance from build → registry → runtime.

4) Kubernetes Security Engineering

  • admission control guardrails (OPA/Kyverno)
  • least privilege runtime execution
  • blast radius reduction & isolation boundaries
  • runtime detections mapped to response actions
Outcome: runtime reality matches security design.

5) Application & API Security

  • broken authorization (IDOR / access control)
  • token handling + session trust boundaries
  • OAuth2/JWT misuse patterns
  • API abuse: replay, enumeration, privilege jumps
Outcome: durable fixes that hold under attacker behavior.

6) Cloud Governance (GCP-first)

  • IAM hardening + privilege reduction
  • secure defaults via org policies
  • drift detection + posture hygiene
  • telemetry aligned to ops + audit
Outcome: governance as guardrails, not documentation.
